# 可审计的基础精剪流水线（v1）

适用于单个原片、原顺序、正常速度的基础精剪。Codex/人工先审查内容、
画面和现场声，再写删除区间；程序只负责执行。不使用 ASR 空白、静音或
VAD 自动决定删点。不确定的内容默认保留，不强制一分钟。

## 运行

需要 Python 3.10+、FFmpeg/FFprobe（含 libx264、AAC 编码器），不需要
Whisper、GPU 或新增 Python 包。推荐沿用现有 Python 3.12 环境。
命令从完整 Skill 安装目录运行：

```powershell
python scripts/edit.py check 'C:\素材\edit-plan.json'
python scripts/edit.py render 'C:\素材\edit-plan.json' --output 'C:\素材\精剪-v1'
python scripts/edit.py verify 'C:\素材\精剪-v1'
```

`render` 自动重新校验、渲染、验收；不依赖先前的 `check` 状态。
输出目录必须不存在。修改删点后输出到新目录，例如 `精剪-v2`。
程序不修改原片、计划或既有结果目录，不会自动安装软件。

FFmpeg 不在 PATH 时，在子命令后传 `--ffmpeg 'C:\工具\ffmpeg.exe'`
和 `--ffprobe 'C:\工具\ffprobe.exe'`；`check` 仅需 FFprobe。
正常执行在 stdout 输出 UTF-8 JSON；通过退出 0，失败退出 1。
命令行用法错误由 argparse 输出帮助并退出 2。

## 计划格式

示例见 [edit-plan.json](../examples/edit-plan.json)。JSON 使用 UTF-8（可带 BOM）。
相对 `source` 路径以**计划所在目录**为基准，不是当前终端目录。

```json
{
  "schema_version": 1,
  "source": "原片.mp4",
  "cuts": [
    {"id": "cut-001", "start": 12.35, "end": 13.10,
     "reason": "同一句开头重启；完整表达保留在后面"}
  ]
}
```

| 字段 | 约定 |
| --- | --- |
| `schema_version` | 必填，整数 `1` |
| `source` | 必填，本地文件路径；不接受网络流 |
| `cuts` | 必填，按源时间排序的删除区间；`[]` 表示完整保留 |
| `cuts[].id` | 必填，唯一非空字符串 |
| `cuts[].start/end` | 必填，有限 JSON 数字，以秒计，`0 <= start < end <= 原片时长` |
| `cuts[].reason` | 必填，具体删除理由；工具只检查非空，理由是否合理仍需内容审查 |
| `source_sha256` | 可选，64 位小写十六进制指纹；不匹配则拒绝执行 |
| `audio_stream` | 可选，FFprobe 的绝对音轨索引；有多条音轨时必须明确选择 |

区间语义是 `[start, end)`，允许相邻，不允许重叠、乱序或删除全部内容。
最多 128 个删点。不会自动排序、修正或合并你的原始决策。
未知字段、重复 JSON 键、非有限数字及不支持的版本全部报错。
`speed`、`overlays` 等字段即使为空或为默认值也不支持，不能借此声明效果已执行。

`check` 返回原片 SHA-256。审查后建议将它写入计划的 `source_sha256`，
防止同一路径文件被替换后误用旧剪点。未填写时，程序记录本次输入指纹，
但无法知道文件是否在先前审查后被替换。渲染前后均检查本次输入未变。

## 时间与媒体约定

- 所有剪点相对于**视频流播放起点**；音频沿用相同时间原点。
- 秒数接受 JSON 数字，推荐写到毫秒；没有毫秒级画面精度的承诺。
- 输出按探测到的名义帧率统一为 CFR；VFR 素材可能重复/丢弃帧以对齐网格。
- 每个删点边界向上对齐到该网格：25 fps 的 `1.01` 秒对应 `1.04` 秒。
  对齐后不包含任何帧的删点报错，不能静默跳过。
- 原片时长优先使用精确的 `duration_ts * time_base`。容器末尾舍入误差在
  一个时间基准 tick 内（最多四分之一帧）时对齐到最近帧，避免无剪辑多出一帧。
- `timeline.json` 同时保存请求删点、实际删点、保留段的源帧/源时间及成片帧/时间。
  照片、章节等后续包装必须使用此成片映射，不直接沿用原片时间。
- 音频按实际帧边界裁切；起始延迟、短于视频的音轨用静音补齐，保留原有相对位置。
  无音轨素材输出也没有音轨，不会伪造旁白或新增音乐。

固定输出为 MP4、H.264/libx264、CRF 18、medium、yuv420p；有音轨时为
AAC 192 kbit/s、48 kHz，保持单声道/双声道数量。沿用原片尺寸，不裁画幅。
只编码最终输出一次；仍属有损转码，不承诺字节级一致。原始字幕、章节和其他
辅助流不复制到基础精剪母版；需要时单独重映射后再制作。

v1 明确拒绝：多视频流/封面图、旋转元数据、非方形像素、隔行、奇数宽高、
HDR/高位深及不支持的像素格式、超过 120 fps、多声道音频、无法确定视频流时长。
多音轨需选轨，不能默认丢掉重要现场声。遇到限制先说明，再选明确的归一化或
已有工具路线；不得自动改原片。这些限制不影响现有转写、下载和视觉配方。
本工具未优化长片/大量删点的资源消耗，不提供局部缓存或断点续渲染。

## 结果与失败

| 文件 | 用途 |
| --- | --- |
| `plan.json` | 原计划快照，原相对路径语义见 `run.json` 中的绝对源路径 |
| `timeline.json` | 派生的实际时间映射 |
| `filter.ffscript` | 本次 FFmpeg 滤镜图 |
| `run.json` | 输入指纹、媒体参数、编码配置、版本、实际参数数组、错误和执行状态 |
| `verification.json` | 时长、画幅、帧率、帧数、音轨、完整解码的机器可读结果 |
| `output.mp4` | 所有自动检查通过后发布的成片 |

渲染暂存为 `output.partial.mp4`。正常失败会清理临时视频，保留失败日志；
强制结束进程或断电可能留下 `.partial.mp4`，它不代表成功，不能交付。
`run.json` 标记 `verified` 且 `output.mp4` 存在后才能交付；可再次执行 `verify`。
重复验收会更新 `verification.json`，同时核对成片、计划、映射和滤镜图指纹，防止拿错版本或误改审计记录。这些指纹用于发现意外变更，不是防篡改签名。
不自动复用失败目录，修复原因后选择新目录重新运行。

验收时长容差为 `max(0.05 秒, 一帧 + 一个 48kHz AAC 包的时长)`；
另外严格核对视频帧数，避免靠放大时长容差掩盖错帧。

**技术通过不等于内容通过。** 报告始终标记 `pending_human_review`。
仍要逐个复核剪口、信息完整性、动作和现场声；没有实际听辨不得宣称已听完校对。
照片动画、画中画、片尾等继续使用已有配方；本工具不代表整项包装任务已经完成。
